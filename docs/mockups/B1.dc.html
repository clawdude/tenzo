The session store keeps access tokens in an encrypted SQLite table with a 24-hour TTL. Both the web app and the CLI read it. Refresh tokens live 30 days, so where they sit changes the threat model: a stolen database now yields long-lived credentials. I can reuse the table, split storage per client, or keep them in memory. Each is a different migration.

Same SQLite table

Safest at rest on a laptop. Adds a native dependency and two storage paths to test. No help for the web app.
In memory only
Nothing to steal from disk. Users sign in again after every restart, which defeats the point of a 30-day token.
