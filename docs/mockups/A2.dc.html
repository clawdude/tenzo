Where should refresh tokens be stored, and should the CLI share the same store as the web app?

You asked for refresh-token rotation on the login flow with a 30-day lifetime. The handler is done and tested against the existing session store, which keeps access tokens in an encrypted SQLite table with a 24-hour TTL and is read by both the web app and the CLI. Refresh tokens live much longer, so where they sit changes both the threat model and the migration.
